# План реализации «ПДД Тренер»

Тренажёр теоретического экзамена ГИБДД. Пользователь выбирает не категорию, а **комплект билетов**:
**ABM** (A, B, M, A1, B1) или **CD** (C, D, C1, D1) — внутри комплекта билеты одинаковые.

## 1. Цели продукта

| Цель | Метрика успеха |
|---|---|
| Ученик сдаёт теорию с первого раза | доля «готов к экзамену» → сдал ≥ 85 % |
| Ученик занимается регулярно | DAU/MAU ≥ 35 %, медианная серия ≥ 5 дней |
| Точная симуляция экзамена | правила совпадают с регламентом МВД (тесты на каждое правило) |
| Работа офлайн | 100 % функций без сети, синхронизация при появлении сети |

## 2. Функциональность

### MVP (реализовано в этой итерации)
1. **Билеты** — решение любого билета подряд, статус каждого билета (не начат / без ошибок / N ошибок).
2. **Экзамен по правилам ГИБДД** — 20 вопросов, 4 тематических блока по 5, 20 минут;
   ошибка в блоке → **+5 вопросов из того же блока (с приоритетом той же темы) и +5 минут**;
   2 ошибки в одном блоке, 3 ошибки всего, ошибка в дополнительном вопросе или истечение времени → «не сдал».
3. **Темы** — тренировка по разделам ПДД с показателем освоения темы.
4. **Марафон** — все вопросы банка подряд в случайном порядке.
5. **Работа над ошибками** — вопрос уходит из списка после 2 правильных ответов подряд.
6. **Избранное** и **сложные вопросы** (по личной статистике ошибок).
7. **Статистика** — точность по темам, история экзаменов, карта билетов.

### Дополнительно (то, что стоит добавить сверх оригинала)
8. **Вероятность сдачи экзамена** — точный расчёт по правилам экзамена из байесовской оценки точности по блокам.
9. **Умная тренировка** — адаптивная подборка: слабые темы, новые вопросы, ошибки, вопросы «к повторению».
10. **Интервальное повторение** (система Лейтнера, 5 коробок: 1/3/7/14/30 дней).
11. **Дневная цель и серия дней** (streak).
12. **Справочник дорожных знаков** (векторная отрисовка SVG, без картинок).
13. **Поиск по вопросам**, горячие клавиши (1–5, Enter, S, F), тёмная тема.
14. **Экспорт/импорт прогресса** (JSON) с версионированием схемы и миграциями.
15. **Импорт официального банка** вопросов (40 билетов × 20 вопросов для AB и CD) из открытого JSON-формата.
16. **REST API** — аккаунты, синхронизация прогресса с оптимистичной блокировкой, серверный экзамен (анти-чит: правильные ответы не уходят клиенту до ответа).

## 3. Архитектура (кратко, подробно — `ARCHITECTURE.md`)

```
src/core      — доменная логика (чистый TypeScript, без I/O): экзамен, сессии, SRS, адаптив, статистика
src/content   — банк вопросов, темы, категории, SVG-знаки, импортёры
src/app       — прикладной слой: сервис тренажёра, порты (Storage, Clock)
src/infra     — адаптеры: localStorage, память, файловое хранилище
src/web       — веб-клиент (SPA без фреймворков, ~30 КБ)
src/server    — REST API на node:http (без внешних зависимостей)
tests         — unit, property-based, контентные, архитектурные, интеграционные тесты API
```

Принципы: гексагональная архитектура, детерминированность (сидируемый ГСЧ → воспроизводимые тесты),
строгий TypeScript, ноль runtime-зависимостей, контент как данные (валидация схемы на CI).

| 0. Discovery | правила экзамена, категории, формат банка | ✅ |

| 2. Контент | демо-банк AB/CD, темы, SVG-знаки, импортёр официального банка | ✅ |
| 3. Веб-клиент | все режимы, статистика, настройки, тёмная тема | ✅ |
| 4. API | auth (JWT), sync, серверный экзамен, rate-limit, problem+json | ✅ |
| 5. Качество | typecheck, unit/property/content/architecture/API-тесты, CI, Docker | ✅ |

| 5b. Помощь в сдаче | текст ПДД, шпаргалки, похожие вопросы, план к дате экзамена, время на вопрос, офлайн, отчёты ученика, частые ошибки | ✅ |
| 6. Мобильные клиенты | React Native / Expo, переиспользуют `src/core` без изменений | план |

## 5. Риски

| Риск | Митигирование |
|---|---|
| Изменения ПДД/билетов (обычно 1 марта и 1 сентября) | контент версионируется, импорт нового банка без релиза кода |
| Права на изображения официальных билетов | демо-банк — собственный контент, знаки рисуются кодом; официальный банк подключается импортом |
| Изменение регламента экзамена | правила вынесены в `ExamRules` (конфиг), каждое правило покрыто тестом |
| Потеря прогресса | версионированная схема, миграции, экспорт/импорт, серверная синхронизация |
